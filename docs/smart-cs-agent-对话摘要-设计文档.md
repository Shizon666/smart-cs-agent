## 1. 元信息

见文首。本能力挂在已有 **Checkpointer 短期记忆** 之上；**不是**用户画像 / Store。

---

## 2. 背景与问题

多轮 + Tool + RAG 片段会使 `thread_id` 下 messages 迅速变长，易撑 token、拖慢调用。  
已有 MEM-02（`InMemorySaver`），具备「可压历史」的前提；此前无自动压缩。

---

## 3. 目标与非目标

### 目标

| ID | 目标 |
|----|------|
| G1 | 消息数超过阈值后，自动将**旧轮次**压成摘要，保留最近若干条原文 |
| G2 | 摘要后同会话仍能续聊；姓名/订单号等关键事实尽量保留在摘要中 |
| G3 | 与现有流式、HITL、路由/RAG **兼容**；不新开会话存储 |

### 非目标

| ID | 不做 |
|----|------|
| N1 | 用户画像 / 跨会话 Store |
| N2 | 持久化摘要到磁盘/DB（随 InMemory 进程结束即丢） |
| N3 | 手写自管 `messages` 列表替代 Checkpointer |
| N4 | 按 token 精确计费优化（可用 messages 阈值即可演示） |

---

## 4. 完成定义（用户看见什么）

| # | 场景 | 通过标准 |
|---|------|----------|
| A | 短会话（未达阈值） | 行为与摘要上线前一致；无不必要摘要调用 |
| B | 同会话多轮超过阈值 | 后续仍能回答；可指代较早轮次中的关键事实（摘要保留） |
| C | `/clear` 或关终端 | 摘要与短期记忆一并消失 |

---

## 5. 用户入口与主流程

入口不变：`python -m app.main`。用户无新命令。  
触发时中间件在模型调用前静默压缩历史（可选一行日志，非必须）。

```text
用户本轮话 → 路由/按需 RAG → Agent（checkpointer 拼历史）
                              ↓ 若 messages ≥ 触发阈值
                         SummarizationMiddleware
                              ↓ 旧消息 → 摘要消息 + 保留最近 K 条
                         再调主模型（可流式）
```

## 7. 方案与选型

| 点 | 选型 | 原因 |
|----|------|------|
| 实现 | LangChain `SummarizationMiddleware` | 官方中间件；与 `create_agent` / checkpointer 同栈 |
| 触发 | `("messages", N)`，默认 **N=12** | 易手测；可用 env 覆盖 |
| 保留 | `("messages", K)`，默认 **K=6** | 保留最近对话原文，含工具对 |
| 摘要模型 | 与主对话同一 DeepSeek（`temperature=0` 实例可共用 `get_chat_model`） | 少配置 |
| 提示词 | 客服向中文摘要（姓名、单号、未决问题） | 默认英文偏 coding agent |

**不采用：** 手写截断最近 N 条（丢中间事实）；把 RAG/Milvus 当「摘要存储」。

### 配置（环境变量，可选）

| 变量 | 默认 | 含义 |
|------|------|------|
| `SUM_TRIGGER_MESSAGES` | `12` | 达到该消息条数触发摘要 |
| `SUM_KEEP_MESSAGES` | `6` | 触发后保留的最近消息条数 |

约束：`KEEP < TRIGGER`；非法时回退默认。

## 9. 契约

无新 CLI 命令、无新 HTTP。  
中间件写回的历史仍落在同一 `thread_id` 的 checkpointer 状态中。

---

## 10. 数据与记忆模型

| 类型 | 本期 | 说明 |
|------|------|------|
| 短期记忆 | 有 | Checkpointer messages；摘要替换其中较旧部分 |
| 对话摘要 | 有 | **本会话内**压缩结果，仍属短期记忆治理 |
| 用户画像 | 无 | 禁止称作长期记忆 |

**概念封印：** 摘要 ≠ 画像；摘要 ≠ 知识库。

---

## 11. 风险与开放问题

| ID | 项 | 倾向 |
|----|----|------|
| R1 | 阈值过低 → 频繁摘要费 token | 默认 12/6；演示可临时调低 |
| R2 | 摘要丢失细节 | 提示词强调单号/姓名/未决问题；接受可降级 |
| R3 | 与流式并存 | 摘要在模型调用前完成；不改变 STREAM-01 过滤约定 |

---

## 12. 验收与手测

1. 默认配置下闲聊 2～3 轮：正常，无明显异常摘要。  
2. 设 `SUM_TRIGGER_MESSAGES=6`、`SUM_KEEP_MESSAGES=2`，多轮后仍能答出较早自我介绍的姓名。  
3. `/clear` 后再问姓名 → 不记得。  
4. `--no-mcp` 下摘要仍可用（不依赖 MCP）。
