## 1. 背景与问题

### 现状

| 项 | 现状 | 问题 |
|----|------|------|
| 主链路 | 意图路由 → 按需 `retrieve` → Agent | **可保留**；已优于教程「每轮必搜」 |
| 语料 | `raw/` 多格式已齐，但多数文件过短；`knowledge.txt` 仍带旧品牌痕迹 | 问答深度不够，评测/简历难量化 |
| 双源 | ingest **优先 raw**；完整退款等细则曾主要在 `knowledge.txt` | raw 非空时细则可能**进不了库** |
| 切分 | `CHUNK_SIZE=200` / `OVERLAP=80`（教程向） | 中文政策条款易被撕碎，跨段丢失 |
| 检索 | `TOP_K=5` / `MIN_SCORE=0.35` | 语料变厚后需重标定，不宜空想改花活 |
| 一期范围 | 明确不做 Rerank / 评测平台 / 多 Agent | 本期只做 KB + 轻量调参 |

### 问题一句话

**演示链路有了，但「可检索的业务知识」偏薄、切分偏教程；先补完整真源与合理切分，再谈量化评测。**

### 本设计立场

1. **先语料、后参数、再评测**；不上 Hybrid / Rerank（除非验收证明召回不足）。  
2. **一份 canon 真源**，多格式是加载能力展示与主题分包，**禁止两套手写口径**。  
3. **实时状态**（订单/工单/额度数字）仍走 SQLite Tool；知识库只写政策与「如何理解结果」，不抢 Tool。

合计正文（不含 FAQ 问句重复）目标：**约 1.5～2.5 万汉字**。

### 5.2 每章固定结构（便于切分）

```text
# 标题
> doc_id / 版本 / 生效日

## 适用范围
## 规则正文（建议带条款号，如 3.2.1）
## 例外与边界
## 客服话术要点
## 禁止承诺（防幻觉话术）
## 相关主题（交叉引用 doc_id）
```

### 5.3 必答问题清单（评测与写作验收用）

实现语料时，下列问题必须在 canon 中有**可定位答案**（条款或表格）。后续评测集优先从中抽样。

**套餐 / 产品**

1. 智答云是做什么的？面向哪些客户？  
2. 有哪些标准套餐？试用多久？  
3. 基础版 / 专业版标价与成员上限？  
4. 企业版是否一定支持私有化？  

**额度**

5. 基础版月度 API 额度多少？超额后是否停用？  
6. AI 问答额度与 API 额度是否分开计算？  
7. 超额后如何恢复？是否自动扣费？  

**成员权限**

8. 基础版正式成员上限？  
9. 外部协作者是否占正式名额？  
10. 管理员能否删除审计日志？（应有明确是/否或条件）  

**发票**

11. 是否支持专票？开票周期？  
12. 发票抬头错误如何处理？  

**退款**

13. 哪些情况可全额退？哪些拒退？  
14. 「为什么我申请退款被拒了？」常见原因至少 3 条  
15. 退款到账周期？  

**数据保留**

16. 试用到期后数据是否立刻删除？宽限期多久？  
17. 注销账号后数据保留策略？  

**企业 / SLA / 工单**

18. 企业版是否含专属 CSM / SLA？  
19. 标准工单响应口径（工作日 / 紧急）？  
20. 知识库政策能否代替合同 SLA 数字？（应引导：以合同为准）  

**边界（防抢 Tool / 防编造）**

21. 用户问「ORD002 到哪了」→ **不应**仅靠知识库编状态（路由走 order + Tool）  
22. 库中无依据的定制承诺 → 应答「需查合同 / 升级人工」  

FAQ json 在上述基础上扩展到 **30～40 条**（含口语改写：如「额度超了还能用吗」）。

## 6. 真源、目录与多格式策略

### 6.1 目录约定（实现后）

```text
knowledge/
  README.md                 # 指向本设计 + 入库命令
  canon/                    # 唯一真源（md 为主）
    00_….md … 09_….md
    10_典型客服问答.json    # FAQ 也可只放 canon，再复制到 raw
  raw/                      # ingest 扫描入口（与现 loaders 兼容）
    md/ txt/ html/ csv/ json/ pdf/ docx/
  knowledge.txt             # 见 §6.3，不再作为第二真源
```

### 6.2 派生规则

| 原则 | 说明 |
|------|------|
| 一主题一主文件 | 禁止同一条款在 md 与 pdf 手写两套 |
| 格式服务 Loader 演示 | pdf/docx **由 canon 导出**；csv 放表格型规则 |
| 元数据 | 入库 metadata 至少含 `source`；能带则带 `doc_id` |
| 交叉引用 | 用 doc_id，避免「见上文」无法检索 |

### 6.3 `knowledge.txt` 处理（已拍板倾向）

| 方案 | 做法 | 本期选择 |
|------|------|----------|
| **T1（推荐）** | 改为短说明文件：指引「请使用 canon/raw；本文件不再参与业务口径」；或从 canon 生成只读汇总且 **仅当 raw 为空时** 才被 ingest 读到 | **采用 T1** |
| T2 | 每次从 canon 自动生成完整 txt，并清空 raw 依赖 | 不做（与多格式演示冲突） |

## 7. RAG / 检索逻辑怎么处理

### 7.1 主流程（不变）

```text
用户原文
  → 规则优先 + LLM 补判（intent / need_rag / search_query）
  → need_rag == false：不检索，Agent + Tools
  → need_rag == true ：retrieve(search_query 或原文)
  → 命中片段注入上下文；System 约束依据片段作答
  → 检索失败 / 空 hits：降级提示，不阻断多轮
```

依据：[多轮对话接入 RAG 设计文档](smart-cs-agent-多轮对话接入RAG设计文档.md)。本期 **不** 改为每轮必搜。

### 7.2 参数升级（实现时锁定一档，评测后微调）

| 参数 | 当前（教程向） | A 档建议起点 | 说明 |
|------|----------------|--------------|------|
| `CHUNK_SIZE` | 200 | **500** | 中文条款完整度优先 |
| `CHUNK_OVERLAP` | 80 | **100** | 略增，防句界切断 |
| `SEPARATORS` | 含 `====` 与句号 | 保留，并加入 `\n## `、`\n### ` | 标题优先切 |
| `DEFAULT_TOP_K` | 5 | **5**（可试 4～6） | 先不动，噪声大再降 |
| `MIN_SCORE` | 0.35 | **先保持，入库后用 10 条必答题重标定** | 过严空召回、过松脏片段 |

### 7.3 代码改动范围（最小）

| 模块 | 允许改动 | 禁止 |
|------|----------|------|
| `rag/config.py` | 切分/检索常量 | 无关重构 |
| `rag/ingest.py` | 分隔符、每文件统计日志、metadata | 改路由 |
| `rag/retrieve.py` | 仅当标定需要改默认 limit/阈值说明 | 上 Rerank |
| `app/routing.py` / prompts | 仅文案对齐产品名、强调「无片段不编造」 | 推翻意图枚举（除非必答题暴露缺口） |
| `knowledge/**` | canon + raw 全量更新 | 把业务逻辑写进语料脚本以外的乱目录 |

### 7.4 暂缓能力

Hybrid、Rerank、自动 chunk 调参、向量多 collection 分库——验收 G 未达标且归因于「召回」时再开子设计。

## 11. 风险与回滚

| 风险 | 缓解 |
|------|------|
| 生成内容数字打架 | 黄金数字表 + Phase1 人工抽检 |
| pdf/docx 与 md 不一致 | 只允许单向导出 |
| chunk 过大/过小 | 先锁 500/100，用固定题对比再改 |
| MIN_SCORE 不适配新库 | 入库后标定；记录到决策表 |
| 一次改太多无法归因 | 严格按 Phase；语料与参数分 commit 更佳 |

回滚：保留 git 历史；`ingest --recreate` 可回到旧 raw（若需可从 tag/commit 取回）。
