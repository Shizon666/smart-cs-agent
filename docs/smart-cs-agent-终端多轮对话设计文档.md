## 1. 背景与问题

### 现状

- 入口：`python -m app.main <mode> [-q ...]`，每次 `ainvoke` 只带**当前一句**用户消息。
- `demo` 连跑三问也是三次独立调用，**无会话连续**。
- 已有 RAG / Tools / MCP，但交互形态仍是「脚本单次问答」，演示与实习讲述成本高。

### 问题

1. 无法演示「刚才那个订单」类指代（无多轮）。  
2. 启动路径偏碎（要记 mode / `-q`），不利于一键演示。  
3. 教程仓（`langchain1.2_tutorial` chapter09）已有短期/长期记忆范式，本仓尚未对齐「短期」主路径。

## 3. 完成定义（用户看见什么）

| # | 场景 | 通过标准 |
|---|------|----------|
| A | 启动 | 执行约定命令后出现提示，可输入，无需先选 `faq/weather/...` |
| B | 多轮输入 | 连续两句以上问答；屏幕上有清晰「你 / 助手」区分 |
| C | 退出 | `/exit`（或约定等价命令）后进程正常结束 |
| D | 短期记忆（步②起） | 先告知姓名或订单号，下一句用指代提问，回答能用上上文 |
| E | 清空（步③） | `/clear` 后不再沿用清空前的会话内容 |
| F | 回归 | 政策/订单/天气均在多轮内可测通 |

## 4. 用户入口与主流程

### 入口

```text
推荐：uv run python -m app.main [--no-mcp]
```

### 主流程（目标态）

```text
启动 → 打印帮助（exit/clear）→ 循环：
  读入一行
  → 若 /exit → 结束
  → 若 /clear → 新会话（步③）
  → 否则交给 Agent → 打印助手回复
```

### 异常路径（最小）

| 情况 | 期望 |
|------|------|
| 空回车 | 忽略，继续等输入 |
| Ctrl+C / EOF | 友好退出，不堆栈炸屏（尽力） |
| MCP 不可用 | 与现网一致：可 `--no-mcp` 或降级；不挡多轮本身 |
| 知识库/Milvus 不可用 | 步①可不依赖；后续若附带检索，失败不阻断纯闲聊（待步内拍板） |

## 5. 分期交付

| 步 | 交付物 | 独立验收 | 记忆 |
|----|--------|----------|------|
| **①** | 终端 `input` 循环；默认进聊天 | 能聊、能 `/exit`；**可不记得**上一轮 | 无 |

## 6. 方案与选型

| 点 | 选型 | 原因 |
|----|------|------|
| 交互 | 终端 `input()` 循环 | 与教程 Jupyter 同属 CLI 交互；无前端成本 |
| 短期记忆（步②） | LangGraph `InMemorySaver` + `thread_id` | 对齐 `langchain1.2_tutorial` chapter09；比手写 `self.messages` 更标准 |
| 长期记忆 | 本期不上 | 见非目标 N1 |
| Agent | 继续 `create_agent` 单 Agent | 与现仓一致 |

**对比（不采用）**

- chapter07 手写 `self.messages`：能多轮，但与 chapter09 官方 checkpointer 不一致，实习讲述成本高。  
- Web UI：一期非目标。

## 8. 契约（命令与会话）

### CLI（当前）

| 项 | 约定 |
|----|------|
| 唯一入口 | `python -m app.main` → 多轮 REPL |
| `--no-mcp` | 不加载 MCP |
| 已移除 | `faq` / `weather` / `biz` / `mcp` / `demo` 子命令（政策/业务均在多轮内走路由+Tools） |
| REPL 命令 | `/exit`（及约定别名）退出；`/clear` 步③ 提供；`/help` 可选 |

### 会话（步② 起）

| 字段 | 含义 | 备注 |
|------|------|------|
| `thread_id` | 会话主键 | 同 id 共享短期历史；`/clear` 换新 id |
| checkpointer | `InMemorySaver` | 进程结束即丢 |

### 消息

- 每轮 `invoke`：**只传本轮新用户消息**（步②+checkpointer 时）；由框架拼历史。  
- 步①无 checkpointer 时：允许「无历史」的纯循环，验收不要求记得住。

## 9. 数据与记忆模型

| 类型 | 本期 | 存什么 | 生命周期 |
|------|------|--------|----------|
| 短期记忆 | 步②启用 | 该 `thread_id` 下 messages | 进程内；关终端丢失 |
| 长期记忆 / 用户画像 | **不做** | — | — |
| RAG 知识库 | 已有 | 文档向量 | 与会话无关（业务知识 ≠ 聊天记忆） |
| SQLite 业务库 | 已有 | 订单/工单/额度 | 与会话无关 |

**概念封印**：评审与 README 中禁止把「Milvus / 订单库」称作「用户对话记忆」。

## 11. 验收与手测（按步）

### 步①（当前）

1. `uv run python -m app.main`（最终命令以 README 为准）进入等待输入。  
2. 输入一句闲聊或业务问句 → 有助手输出。  
3. 再输入一句 → 有输出（**不要求**引用上一句）。  
4. `/exit` → 进程结束。  
5. 多轮内再问超额 / ORD002 / 天气 → 仍可用（回归）。

### 步②（授权后）

1. 同一会话：「我叫张三」→「我叫什么？」→ 答含张三。  
2. 新开进程后同问 → 不应再记得（InMemory 特性，作为说明点）。

### 步③（授权后）

1. 建立记忆后 `/clear`，再问姓名 → 不记得。  
2. README 按文档可完成启动与上述演示。
