# 01 — 开发流程

每次加功能按下面走（可裁剪，不可跳验收）。

```text
钉需求（可验收）→ 对照标准（结构/命名/技术）→ 实现 → 手测 → 更新 README/文档
```

## 步骤

1. **钉需求**  
   写清：用户从哪进、看见什么算完成、本期不做啥。

2. **对标准**  
   改动落在哪个模块？是否违反依赖方向？命名是否符合规范？  
   **M/L 级**：先补设计文档（命名与维度见 [smart-cs-agent-终端多轮对话设计文档](smart-cs-agent-终端多轮对话设计文档.md) 第 0 节；命名规则亦见 [命名规范](02-开发标准/命名规范.md)），再写码。

3. **实现**  
   只改相关模块；禁止为图快把逻辑堆进 `app/main.py`。

4. **验收**  
   走 [03-验收与手测](03-验收与手测.md)；改行为必须有 L2 手测。

5. **留痕**  
   若变更选型或边界，追加 [04-决策记录](04-决策记录.md)。

## 优先级（一期）

```text
仓库骨架（当前）
  → rag 入库/检索
  → 本地天气 Tool
  → app 单 Agent 串起 FAQ+天气
  → 接入 mcp_server
  → README 演示一键可跑
```

## 任务分级（习惯）

| 级 | 例子 | 要求 |
|----|------|------|
| S | 改文案、修命名 | 最小改 + 自测 |
| M | 一个 Tool / 一条 API | 对照标准 + 手测 |
| L | 新模块、多 Agent | 先补设计再写码 |
