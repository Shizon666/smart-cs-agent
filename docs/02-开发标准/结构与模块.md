# 结构与模块

## 目录

```text
smart-cs-agent/
├── app/                 # 应用层：入口 + 单 Agent + prompts
├── rag/                 # RAG 领域
├── tools/               # 本地工具（进程内）
├── mcp_server/          # MCP 工具进程（进程外）
├── knowledge/           # 知识库语料
├── evals/               # 评测题集 + 跑分脚本（依赖 app/rag）
├── docs/                # 工程文档
├── tests/               # 后续补测
├── .env.example
└── pyproject.toml
```

## 依赖方向（强制）

```text
app → rag | tools |（连接）mcp_server
evals → app | rag
rag ↛ app
tools ↛ app | rag
mcp_server ↛ app | rag | tools
evals ↛ 被 app/rag/tools 引用
```

## 模块职责

| 模块 | 负责 | 不负责 |
|------|------|--------|
| `app` | 对话入口、注册 tools、调度、prompt | 向量细节、SMTP 实现 |
| `rag` | 切分、Embedding、Milvus、retrieve、ingest | 天气、MCP 协议 |
| `tools` | 本地 Tool（如 weather） | 启动 MCP、写库 |
| `mcp_server` | 新闻/舆情/邮件等 MCP tools | 聊天入口 |
| `evals` | 题集 CSV、批量跑分、汇总表 | 改业务路由/工具实现 |

## 单 Agent → 多 Agent 预留

- 一期：`app/agent.py` 一个 Agent，挂全部 tools  
- 二期：总控 + 子 Agent；子 Agent 只依赖 `rag`/`tools`/`mcp_server`，互不引用

## 模块内文档约定（开发标准）

**算开发标准，必须遵守：**

| 要做 | 不要做 |
|------|--------|
| 每个顶层业务包保留一份短 `README.md`（职责表 + 怎么跑 + 边界） | 不要给每个小 `.py` 再单独写一篇 docs |
| 文件顶可用 1～2 行 docstring/注释说明职责 | 不要把实现细节复制进长文档（易过期） |

当前已覆盖：

- `app/README.md`
- `rag/README.md`
- `tools/README.md`
- `mcp_server/README.md`
- `evals/README.md`

新建顶层包（如二期 `app/agents/`）时：同步补短 README，并更新本文目录示意。

仓库级规范仍以 `docs/` 为准；包内 README 是「就近导航」，二者不重复写两套长文。
