# 命名规范

## 通用

| 类型 | 风格 | 示例 |
|------|------|------|
| 包/模块/文件 | snake_case | `mcp_server`, `vectorstore.py` |
| 函数/变量 | snake_case | `retrieve`, `get_weather` |
| 类 | PascalCase | `VectorStore`（若需要类） |
| 常量 | UPPER_SNAKE | `MILVUS_URI`, `EMBED_DIM` |
| 工具名（给模型看） | 英文动词短语 | `get_weather`, `search_google_news` |

禁止：工具/核心 API 用中文函数名；description 可用中文。

## 环境变量

| 变量 | 用途 |
|------|------|
| `DEEPSEEK_API_KEY` / `BASE_URL` / `MODEL` | 对话模型 |
| `SILICONFLOW_API_KEY` / `SILICONFLOW_BASE_URL` | Embedding |
| `SERPER_API_KEY` | 新闻搜索 |
| `SMTP_*` / `EMAIL_*` | 邮件 |
| `MILVUS_URI`（可选） | 默认 `http://localhost:19530` |
| `LANGSMITH_TRACING` / `LANGSMITH_API_KEY` / `LANGSMITH_PROJECT`（可选） | LangSmith 追踪；见教程仓同款环境变量 |

## RAG / 存储层命名（大厂常见叫法）

业界很少在业务包里再叫一个泛泛的 `client.py`（太容易和「业务 Client / MCP Client / HTTP Client」混）。

更常见：

| 职责 | 常见命名 | 本仓库采用 |
|------|----------|------------|
| 向量化 | `embeddings.py` / `embedding.py` | **`rag/embeddings.py`** |
| 向量库读写 | `vectorstore.py` / `vector_store.py` / `store.py` | **`rag/vectorstore.py`** |
| 入库流水线 | `ingest.py` / `indexer.py` | **`rag/ingest.py`** |
| 检索 | `retrieve.py` / `retriever.py` | **`rag/retrieve.py`** |
| 配置 | `config.py` | **`rag/config.py`** |

说明：

- LangChain 生态也常用 **Embeddings** + **VectorStore** 这对概念。  
- 若将来抽象接口，可用 `VectorStore` 类，文件仍叫 `vectorstore.py`。  
- **禁止**再使用 `rag/client.py` / `rag/clients.py`。

## 应用入口

- 模块：`app.main`  
- 命令：`python -m app.main`  
- 旧项目的 `client.py`（MCP 聊天入口）在新仓中对应 **`app/`**，不再叫 client。

## 功能设计文档（多仓库可辨）

| 项 | 约定 |
|----|------|
| 本仓库全名 | `smart-cs-agent` |
| 本仓库缩写 | **SCA**（文内须写明全名） |
| 推荐文件名 | `{仓库名}-{功能简述}-设计.md` |
| 可选文件名 | `{缩写}-{功能简述}-设计.md` |
| 存放 | `docs/` |
| 示例 | `smart-cs-agent-终端多轮对话-设计.md` / `SCA-终端多轮对话-设计.md` |

禁止：看不出仓库的名字（如 `设计.md`、`05-设计-xxx.md`）。  
维度与模板见现有功能设计文第 0 节。

## Git（若使用）

- 分支：`feat/...`, `fix/...`, `docs/...`  
- 提交前缀：`feat:` `fix:` `docs:` `refactor:`
