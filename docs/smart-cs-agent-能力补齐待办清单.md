## 2. 分项说明

### P0 · MEM-02　短期记忆（Checkpointer）　**L**

| 项 | 内容 |
|----|------|
| **要做什么** | Agent 挂 `InMemorySaver`；同 `thread_id` 多轮只传本轮用户消息，由框架拼历史 |
| **完成定义** | 「我叫张三」→「我叫什么」能答对；「刚才那个订单」类指代在同会话内可用（演示口径） |
| **依据** | [终端多轮设计](smart-cs-agent-终端多轮对话设计文档.md) 步②；选型 `InMemorySaver`（进程内，关终端丢） |
| **主要改动面** | `app/agent.py`（挂 checkpointer）、`app/chat.py` / `main.py`（传 `thread_id` / config） |
| **不做** | Postgres 等持久化 checkpointer；Store / 用户画像 |
| **动手前** | 设计文档已有 → 实现前核对契约是否与当前 `create_agent` API 一致；若 API 变更，先改设计再写码 |
| **验收手测要点** | 同进程两轮指代；重启进程后应失忆 |

### P1 · MEM-03　`/clear` + 文档　**M**

| 项 | 内容 |
|----|------|
| **要做什么** | REPL `/clear` 换新 `thread_id`（或清空该 thread）；README 写明用法 |
| **完成定义** | `/clear` 后再问「我叫什么」不再答出旧名；文档可照做 |
| **依据** | 终端多轮设计步③ |
| **主要改动面** | `app/chat.py`（或等价 REPL）、`README.md` |
| **验收手测要点** | 有记忆 → `/clear` → 失忆；`/help` 含 `/clear` |

---

### P2 · STREAM-01　流式输出　**M**

| 项 | 内容 |
|----|------|
| **要做什么** | 终端对**最终助手回复**做 token/块级流式打印（替代整段 `ainvoke` 再刷屏） |
| **完成定义** | 闲聊/政策问答可见逐字或逐块输出；工具调用轮次不把中间态打乱成乱码 |
| **主要改动面** | `app/chat.py`（或调用 Agent 处）；必要时薄封装 stream 消费 |
| **风险** | Tool Calling 多轮事件与最终文本混流 → 需约定「只流式最终 AI 文本」或等价过滤 |
| **流式事件过滤约定（已落地）** | 用 `astream_events` v2；仅打印 `on_chat_model_stream` 且 `content` 非空的片段；`on_tool_start` 打印一行 `（调用工具: name）`；忽略工具规划轮的空 chunk |
| **动手前** | M 级：可在本清单下补一小节「流式事件过滤约定」或短设计段落，再写码 |
| **验收手测要点** | 纯问答流式；带天气/查单工具时最终答案仍流式且可读；Ctrl+C 行为可接受 |
| **状态** | **已完成**（2026-09-15） |

### P3 · HITL-01　高危工具人工确认　**M**

| 项 | 内容 |
|----|------|
| **要做什么** | 对 `send_email_with_attachment`（及明确列出的高危工具）执行前 CLI 确认；拒绝则不发送并告知用户 |
| **完成定义** | 触发发信工具 → 终端提示确认 → `n` 不发、`y` 才发 |
| **主要改动面** | MCP 工具包装 / Agent 中间件 / 或 chat 层拦截（实现时选一种，保持模块边界） |
| **不做** | 完整 HITL 平台、Web 审批流、对天气/查单也弹确认 |
| **验收手测要点** | 确认发送成功路径；拒绝路径无真实发信；`--no-mcp` 下不出现该确认 |
| **落地** | `app/hitl.py` 包装 MCP 工具（非 LangGraph interrupt）；`build_agent` 加载 MCP 后 `apply_cli_hitl` |
| **状态** | **已完成**（2026-09-15） |

### P4 · SUM-01　对话摘要（压历史）　**L**

| 项 | 内容 |
|----|------|
| **要做什么** | 当同 `thread_id` 消息过长时，将旧轮次压缩为摘要再续聊（腾 token） |
| **完成定义** | 人为拉长多轮后仍能续聊且不轻易爆上下文；摘要后关键事实（如已报过的订单号）仍可用或可接受降级 |
| **依赖** | **必须先有 MEM-02**；无 Checkpointer 时手写摘要收益小且路径分叉 |
| **与画像区别** | 摘要 = **本会话历史压缩**；画像 = **跨会话长期偏好/身份** → 见非目标，勿混写 README/简历 |
| **动手前** | **L：先补设计文档**，建议命名：`smart-cs-agent-对话摘要-设计文档.md`（触发阈值、保留最近 K 轮、摘要写入 checkpointer 的方式） |
| **落地** | 设计见 `docs/smart-cs-agent-对话摘要-设计文档.md`；`SummarizationMiddleware` + `SUMMARY_PROMPT`；阈值 env 可调 |
| **验收手测要点** | 短会话不乱摘要；长会话触发后仍能指代；关终端后摘要与短期记忆一并丢失（与 InMemory 一致） |
| **状态** | **已完成**（2026-09-15） |

### P5 · RETRY-01　轻量重试（可选）　**S～M**

| 项 | 内容 |
|----|------|
| **要做什么** | 对模型调用或关键 Tool 的瞬时失败做有限次重试（次数/退避写死或进配置） |
| **完成定义** | 可演示或日志可见「失败后重试再成功」；不是无限打爆 API |
| **建议口径** | 工程兜底即可；**简历勿写成「限流/重试中间件治理全家桶」** |
| **不做** | 完整限流网关、令牌桶集群方案 |
| **验收手测要点** | 人为制造一次可恢复失败（或 mock）见重试；超次数后友好报错 |
| **落地** | `ModelRetryMiddleware` + `ToolRetryMiddleware`；`RETRY_MAX_RETRIES`（默认 2，0 关闭） |
| **状态** | **已完成**（2026-09-15） |
